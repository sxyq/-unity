# 服务器端植入方案调研

> 调研对象：`https://skeletaltraction.cqmu.edu.cn`（重庆医科大学护理学院 · 虚拟仿真实验教学平台，梦之路 Mengoo）
> 调研时间：2026-11-14
> 工具：REA 6.9.0（Node 22.23.5）+ 手工取证 + 本地反向代理预演
> 结论适用范围：校内授权环境、仅用于教学增强，不改变原系统评分

---

## 0. 一句话结论

**能在服务器上植入，而且不需要厂商源码。** 最稳的方式不是改原系统文件，而是在它前面加一层反代：
返回 HTML 时插一行 `<script>`，再把 `/mengoo/__ai/` 指到我们的服务。

三条边界必须说清：

| 想拿到的 | 服务器端植入能否拿到 | 原因 |
|---|---|---|
| 页面级状态（哪个实验、考核页、成绩表） | ✅ 能 | 都在平台网页里，hook 脚本能读 |
| 学生不需要装扩展 | ✅ 能 | 服务端注入，浏览器无感 |
| 实验内部步骤（术中第几步、牵引参数） | ❌ 不能 | 实验跑在 `MLauncher://` 拉起的 Windows 客户端里，不在网页进程中 |

第三行是形态决定的，不是实现问题。服务器端植入解决的是"分发"，不是"跨进程读状态"。

## 2. 服务器侧实测证据

### 2.1 响应头（决定用哪种注入方式）

```
GET /mengoo/                       → 200  Content-Type: text/html  Content-Length: 5423
                                        Server: rump/e
                                        Last-Modified: Tue, 12 Nov 2024 03:24:02 GMT
                                        ETag: "6732ca52-152f"   Accept-Ranges: bytes
GET /mengoo/static/js/index...js   → 200  application/javascript  1,236,669 B
GET /MZL/MLauncherSetup.msi        → 200  application/octet-stream 82,271,744 B
                                        X-Powered-By: ASP.NET
GET /api/__nope                    → 404  X-Powered-By: ASP.NET   Transfer-Encoding: chunked
```

判读：

| 观察 | 含义 |
|---|---|
| `X-Powered-By: ASP.NET`（连 404 都有） | 后端是 **ASP.NET**，所有请求都进 .NET 管道 |
| 静态文件有 `ETag: "hex-hex"` + `Last-Modified` + `Accept-Ranges` | 典型 IIS 静态文件处理器特征（nginx 也可能，但配合上一行更偏 IIS） |
| `Server: rump/e` | 非标准值，像是被安全设备/加固策略改写过的标识，**不能据此判断 nginx/IIS** |
| 只支持 HTTP/1.1（`--http2` 协商回 1.1） | 老式 IIS 或未开 h2 的 nginx |
| `/mengoo/` 的 `Last-Modified` 是 2024-11-12 | 前端是**构建产物**，升级会整体替换 `/mengoo/static/*` 与 `index.html` |

**这条最关键**：`index.html` 是构建产物，**直接改文件在下次升级时会被覆盖**，所以首选反代注入而不是改文件。

### 2.2 入口 HTML 结构（注入点）

```html
<!doctype html><html lang="zh-cmn-Hans"><head>
  <meta charset="UTF-8"/>
  <title>虚拟仿真实验教学平台</title>
  <script type="module" crossorigin src="/mengoo/static/js/index.175edf5....js"></script>
  ... 46 个 modulepreload ...
  <link rel="manifest" href="/mengoo/manifest.webmanifest">
  <script id="vite-plugin-pwa:register-sw" src="/mengoo/registerSW.js"></script>
</head><body><div id="app"><div id="appLoading"></div></div></body></html>
```

三个好消息：

1. **没有 CSP**（无 `Content-Security-Policy`），外链脚本不会被拦；
2. 没有 SRI（`integrity`），注入不会破坏校验；
3. `</head>` 唯一且干净，`sub_filter` 一行就够。

一个坏消息（见 §6.1）：**注册了 Service Worker**，会缓存 `index.html`。

### 2.3 PWA / Service Worker（这是最容易翻车的点）

```
/mengoo/registerSW.js  → 148 B
  navigator.serviceWorker.register('/mengoo/sw.js', { scope: '/mengoo/' })

/mengoo/sw.js          → workbox precache 清单，第一条就是
  { url: "index.html", revision: "987c8f20032d0b746aa985984ddb406a" }
```

含义：**已经访问过的学生，浏览器会用 SW 缓存里的 `index.html` 直接返回，请求根本不到服务器**，
反代注入的 `<script>` 不会出现在页面里。

这不是理论风险，是必然发生。处理方式见 §6.1。

## 3. 接口盘点：平台到底有什么

从主包 `index.175edf5....js` 静态提取，共 **144 个接口**（`lt.post/get("...")`）：

| 分类 | 数量 | 说明 |
|---|---|---|
| `/OrgApi/*` | 87 | 教师/管理端（组织、课程、题库、统计） |
| `/api/*` | 18 | 学生端主接口 |
| 其他（`/template/*` 等） | 39 | 静态配置与站点骨架 |

### 3.1 与本次需求直接相关的

| 接口 | 方法 | 能否读 | 用途 | 已实测 |
|---|---|---|---|---|
| `/api/Experiment/Items` | POST | ✅ 免登录 | 实验列表（含 `type/typeName`） | ✅ 200 |
| `/api/Experiment/Item` | POST | ✅ 免登录 | 实验详情：`type:2 客户端实验`、`url:"HLF10631030"` | ✅ 200 |
| `/api/auth/UserNamePwd` | POST | — | 登录（密码前端 AES） | ✅ 契约已抓 |
| `/api/Auth/Info` | POST | 需登录 | 当前用户 | ✅ 登录后可用 |
| `/api/Experiment/Launch` | POST | 需登录 | **返回 `MLauncher://` 启动串** | ✅ 实测 |
| `/api/Experiment/Start` | POST | 需登录 | 点"启动"时上报 | ✅ 实测 |
| `/api/Experiment/GetProcess` | POST | 需登录 | 学习进度 `{ppv,studyeds,timeUsed}` | ✅ 实测 |
| `/api/ExperimentResult/ItemsByUser` | POST | 需登录 | 成绩记录（98/88/68） | ✅ 实测 |
| `/api/open/ScormDataUpload` | POST | 平台内部 | 实验内容上报**步骤**（`///` 协议） | 静态确证 |
| `/api/open/JsDataUpload` | POST | 平台内部 | 实验内容上报**结果/成绩**（`***` 协议） | 静态确证 |

### 3.2 一个容易误判的接口

`/OrgApi/InteractiveQA/Add|Items|Update|Delete|Upvote|Hits|SelectedQA|SonItems`

看起来像"互动问答"，**实际是教师端的题库 CRUD**（挂在 `/OrgApi/` 下，和 `OrgCats`、`Experiment` 管理接口同一组）。
**它不是聊天接口，也不是学生端问答通道**，不能拿来当 AI 对话的落点。

### 3.3 结论

- 平台**没有任何 AI/LLM 接口**（全包搜 `chat/completions`、`openai`、`gpt`、`大模型` 均 0 命中）；
- 平台有**完整的实验状态与成绩接口**，但都要登录态；
- 平台有**实验→平台的单向上报通道**（`ScormDataUpload` / `JsDataUpload`），这是唯一由平台自己定义的"实验内部数据出口"。

所以：**AI 必须外挂，数据必须自己接。** 这决定了下面的架构。

## 4. 四种植入拓扑

### T1 直接改 `index.html`（最省事，最脆）

| 项 | 内容 |
|---|---|
| 改什么 | `mengoo/index.html` 的 `</head>` 前加一行 `<script src="/mengoo/__ai/hook.js" defer>` |
| 需要权限 | 服务器文件写权限 |
| 优点 | 5 分钟完成，无额外组件 |
| 缺点 | **升级即被覆盖**；多节点要逐台改；没有灰度 |
| 回滚 | 删那一行 |
| 适用 | 一次性验收演示、单机部署 |

### T2 前置反代注入（推荐）

| 项 | 内容 |
|---|---|
| 改什么 | nginx `sub_filter` 或 IIS 出站规则，插入同一行 script |
| 需要权限 | 能改 Web 服务器配置（通常信息化中心就有） |
| 优点 | **不碰原系统文件**；升级不受影响；可灰度（按 IP/网段）；可一键关闭 |
| 缺点 | 多一层反代，需要处理压缩、SSE、SW 缓存 |
| 回滚 | 注释掉 location，reload |
| 适用 | 正式上线 |

### T3 平台后端加中间件

| 项 | 内容 |
|---|---|
| 改什么 | ASP.NET 加一个 middleware / 新 Controller |
| 需要权限 | **厂商源码 + 厂商配合** |
| 优点 | 最彻底：可以正式发 token、写库、加权限 |
| 缺点 | 项目周期以周计；涉及厂商商务；升级要重新合并 |
| 适用 | 学校决定长期共建时 |

### T4 客户端回传（唯一能拿"术中步骤"的路）

| 项 | 内容 |
|---|---|
| 改什么 | 在 Unity 客户端里调 `window`/HTTP 回调，把 `///步骤`、`***成绩` 发给平台 |
| 需要权限 | 厂商客户端源码 |
| 优点 | 真正打通实验内部状态 |
| 缺点 | 不属于"服务器植入"，工作量在客户端 |
| 备注 | 平台的 `ScormDataUpload` 接口**已经就绪**，缺的只是客户端没发 |

### 对比

| 维度 | T1 改文件 | T2 反代 | T3 中间件 | T4 客户端 |
|---|---|---|---|---|
| 需要厂商 | 否 | 否 | 是 | 是 |
| 升级安全性 | ❌ 被覆盖 | ✅ | ⚠️ 需合并 | ⚠️ |
| 学生免装扩展 | ✅ | ✅ | ✅ | ✅ |
| 灰度/回滚 | 弱 | ✅ | 中 | 弱 |
| 拿页面级状态 | ✅ | ✅ | ✅ | ✅ |
| 拿实验内部步骤 | ❌ | ❌ | ❌ | ✅ |
| 落地周期 | 0.5 天 | 1–2 天 | 2–4 周 | 4 周+ |

**推荐：T2 为主，T1 作为兜底演示；T4 作为二期，向厂商提需求。**

## 5. 推荐架构

```
学生浏览器
   │  https://skeletaltraction.cqmu.edu.cn/mengoo/
   ▼
┌──────────────────────────────────────────────┐
│ nginx（新增，或复用现有）                      │
│  ├─ /mengoo/       → 原站，sub_filter 插 script│
│  ├─ /mengoo/__ai/  → 127.0.0.1:8788（我们）   │
│  └─ 其他            → 原站，原样转发            │
└──────────────────────────────────────────────┘
        │                          │
        ▼                          ▼
   原平台（不动）            apps/server-inject/service.mjs
   ASP.NET + 静态 SPA          ├─ hook.js（94 KB，前端全量）
                               ├─ /api/chat → 模型网关（SSE）
                               └─ /api/health
                                        │
                                        ▼
                               apps/model-gateway/server.mjs
                               （Key 只在这里 / 环境变量）
```

分工：

- **hook.js**：复用现有 `apps/apps/extension/src/*` 全部逻辑（十场景、四功能名、考核保护、埋点、成绩解析），
  只把 `chrome.runtime` 换成 fetch+SSE（`src/web-shim.js`，约 120 行）；
- **service.mjs**：静态托管 + 对话转发 + 限流 + 可选登录校验；
- **原系统**：一行不改，评分、流程、客户端全部照旧。

## 6. 六个必须提前解决的技术坑

### 6.1 PWA 缓存（最容易翻车）

`sw.js` precache 了 `index.html`。老用户不会请求服务器，注入失效。

三种处理，按推荐排序：

1. **让 `/mengoo/sw.js` 返回 404**（反代里加一条 `location = /mengoo/sw.js { return 404; }`）
   —— 实验室场景不需要离线能力，代价最小；已注册的 SW 会在下次更新检查时被清掉。
2. 在 `sw.js` 的 precache 清单里加 `hook.js`，并把 `index.html` 的 revision 改掉，强制更新。
3. 在 `sw.js` 里加 `fetch` 拦截，对 `navigate` 请求做字符串注入（复杂度最高）。

### 6.2 压缩

`sub_filter` 匹配不到 gzip 后的 HTML，必须 `proxy_set_header Accept-Encoding "";`
IIS 侧则是关掉静态压缩。

### 6.3 SSE 被缓冲

nginx 默认缓冲上游响应，流式回答会变成"一次性吐出来"。必须：
`proxy_buffering off;`，同时服务端已返回 `X-Accel-Buffering: no`。

### 6.4 升级覆盖

`/mengoo/` 是构建产物。T2 不受影响；T1 每次升级要重做。
建议把注入做成配置项（include 一个小文件），升级时只检查这一处。

### 6.5 WAF / UA

实测：`HeadlessChrome`、`python-requests` 这类 UA 会被直接 RST。
**注入本身不受影响**（是服务器自己回 HTML），但任何服务端主动抓取/自检脚本都要用正常浏览器 UA。

### 6.6 鉴权与刷量

`/mengoo/__ai/api/chat` 一旦公开，等于给全校一个免费 LLM 入口。三层防护：

1. `AUTH_CHECK=1`：服务端拿 Cookie 调平台 `/api/Auth/Info`，未登录 401（已实现）；
2. nginx `limit_req`：20 次/分钟/IP（配置已给）；
3. 模型侧配额与日志：按用户/会话计量，异常告警。

## 7. 能不能通过：审批与技术审查

### 7.1 谁会签字

| 角色 | 关心什么 | 我们要给的 |
|---|---|---|
| 教务处 / 护理学院 | 教学效果、是否影响原考核 | 只增不减、不碰评分、可关闭 |
| 信息化中心 | 安全、稳定、可回滚 | 不改原系统、反代可灰度、单点可下线 |
| 厂商（梦之路） | 是否改他们的东西、责任边界 | 我们不改前端/后端文件，只在外层加壳 |
| 网信/等保 | 数据出境、个人信息 | 不采集患者与账号，Key 在校内 |

### 7.2 技术审查清单（建议逐条写进立项材料）

1. 是否修改原系统文件 → **否**（T2）
2. 是否影响原评分与成绩上传 → **否**，只读页面
3. 是否收集个人信息 → **否**，只记录场景 ID 与耗时，不落对话原文
4. 模型 Key 存哪 → **服务器本地配置文件 / 环境变量**，前端零密钥
5. 能否一键关闭 → **能**，删 location 即恢复
6. 是否有单点故障 → **有**，但故障时只掉面板，不影响原系统（脚本加载失败即静默）
7. 性能影响 → hook.js 94 KB（gzip 后约 30 KB），对话走异步 SSE，不阻塞页面
8. 是否影响离线/PWA → 会关闭 SW（实验室场景无影响），需提前说明
9. 日志与审计 → 本地埋点 600 条环形缓冲，可导出；不主动上传
10. 异常兜底 → 未识别场景时只显示"手动选择"，绝不猜测

### 7.3 三条红线（写进承诺）

- 不写任何成绩、不伪造完成状态、不调用 `ScormDataUpload`/`JsDataUpload`
- 不读 token/Cookie 用于业务，登录校验只做"是否已登录"的布尔判断
- 不在考核模式给出题目答案（已有实现：红色徽标 + 拒答）

### 7.4 结论

**按 T2 方案，通过的概率高。** 因为它把改动收敛到"Web 服务器加一段配置"，
原系统零改动、可灰度、可秒级回滚——这正是信息化中心最愿意看到的形态。

真正会被卡住的是两件事，且都不在技术侧：

1. **谁来维护**：反代配置属于学校资产，需要明确运维责任人；
2. **模型费用与合规**：校外 API 还是校内私有化部署，需要教务处/网信办拍板。

## 9. 已完成的预演验证（不是纸上方案）

| 项 | 结果 |
|---|---|
| 注入方式 | 本地反向代理在真实站点 HTML 的 `</head>` 前插 `<script>` |

## 11. 复述结论

- **技术上可行**：T2 反代注入 + 本地服务，已在真实站点预演通过，原系统零改动。
- **接口上够用**：实验身份、成绩、进度都能从平台接口/页面拿到；AI 对话自己带。
- **形态上有天花板**：术中步骤在 Windows 客户端内，服务器植入拿不到，只有 T4（厂商配合）能解。
- **审批上可谈**：改动收敛在 Web 服务器配置，可灰度、可回滚、不碰评分，是最容易被接受的形态。
