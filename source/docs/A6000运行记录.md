# 在 A6000 服务器上跑通客户端（2026-11-14 实测）

> 机器：`syy@10.16.15.202`（k3s-infra-01，80 核 / 376 GB / RTX A6000，Ubuntu 24.04，x86_64）
> 结果：**客户端起来了，Unity 初始化成功，C# 业务脚本加载成功，日志写出来了。**
> 与之前 ARM Mac 上 Docker 模拟的失败形成对照：那是架构问题，不是 Wine 的问题。

---

## 1. 为什么用"便携版 Wine"而不是 apt

服务器没有公网出口，`syy` 也没有免密 sudo：

| 检查 | 结果 |
|---|---|
| `curl https://github.com` | 超时（无外网） |
| 本机 clash 7890 | 返回 502，代理链路不可用 |
| `sudo -n true` | 需要密码 |
| docker socket | `root:docker 660`，用户不在 docker 组 |

所以走**完全免安装**的路线：把 Wine 打包传上去，解压即用。

```bash
# 本机（有代理）下载，SHA256 校验后 scp
wine-11.21-amd64-wow64.tar.xz   93 MB   33f3c5b5…fb9dc83
```

选 `wow64` 版本的原因：客户端是 **32 位 x86**（PE 0x014c），而 Ubuntu 24.04 默认没有 i386 库；
Wow64 版能在纯 64 位系统上跑 32 位程序，正好绕开这个限制。

## 2. 完整可复现步骤

### 2.1 服务器上

```bash
mkdir -p ~/mengoo && cd ~/mengoo
tar -xJf ~/wine.tar.xz          # wine-11.21-amd64-wow64/
tar -xzf ~/app2.tgz             # 从 MLauncherSetup.msi 解出的客户端

# 关键 1：开 GLX 的虚拟显示（默认 Xvfb 没有 GLX，Wine 连记事本都起不来）
nohup Xvfb :103 +extension GLX +extension RANDR +render -noreset \
      -screen 0 1280x800x24 >/tmp/x103.log 2>&1 &

export DISPLAY=:103
export WINEPREFIX=$HOME/mengoo/prefix
export WINEDEBUG=-all

~/mengoo/wine-11.21-amd64-wow64/bin/wineboot -u      # 约 15 秒建好前缀

# 关键 2：强制 D3D11（默认会先试 Vulkan，报 apiVersion=0 后崩溃）
cd ~/mengoo
~/mengoo/wine-11.21-amd64-wow64/bin/wine \
  app2/MCLocalLauncher.exe -force-d3d11 -screen-fullscreen 0 \
  -screen-width 1280 -screen-height 800
```

### 2.2 客户端目录必须摆对

MSI 里的文件名和 Unity 期望的不一致，三处必须手动修正，否则脚本/着色器加载不出来：

| MSI 里的名字 | 必须放成 |
|---|---|
| `mono2.0bdwgc.dll` | `MonoBleedingEdge/EmbedRuntime/mono-2.0-bdwgc.dll` |
| `AssemblyCSharp.dll` | `MCLocalLauncher_Data/Managed/Assembly-CSharp.dll`（带横线） |
| `unitydefaultresources` | `MCLocalLauncher_Data/Resources/unity default resources`（带空格） |
| `unity_builtin_extra` | `MCLocalLauncher_Data/Resources/unity_builtin_extra` |

不修第 2 条时，日志会刷：

```
The referenced script (SelfUpdater) on this Behaviour is missing!
The referenced script (AppComponent) on this Behaviour is missing!
```

修完后业务代码就跑起来了。

## 3. 实测证据（`docs/evidence-real-player-log.txt`）

```
Mono path[0] = 'Z:/home/syy/mengoo/app2/MCLocalLauncher_Data/Managed'
Initialize engine version: 2019.3.14f1 (f8ba459ea890)
GfxDevice: creating device client; threaded=1
Direct3D:
    Version:  Direct3D 11.0 [level 11.1]
    Renderer: NVIDIA GeForce GTX 470 (ID=0x6cd)     ← wined3d 的占位显卡名
<RI> Input initialized.
CommandLineArgs:4
GetProcessesByName MCLocalLauncher  null
CommandLineArgs:-force-d3d11
Application_StartError
```

最后一行 `Application_StartError` 是**预期**：启动器需要平台下发的
`MLauncher://&<实验代码>&…&ticket…` 参数，而这台机器到不了平台
（`curl` 校内域名超时，IPv6 也不通），所以它进了错误分支。

### 顺带验证了我们要的那件事

不传 `-logFile` 时，日志确实写在：

```
C:\users\syy\AppData\LocalLow\Mengoo\MCLocalLauncher\Player.log
```

也就是 `client-agent` 在 Windows 上找的那个路径。**路径假设从"推导"变成了"实测"。**

## 4. 这次证明了什么、没证明什么

| 结论 | 状态 |
|---|---|
| 客户端能在 x86_64 Linux + Wine 上启动 | ✅ 实测 |
| Unity 2019.3 引擎初始化、D3D11 设备创建 | ✅ 实测 |
| C# 业务程序集能加载（启动器逻辑执行到 StartError） | ✅ 实测 |
| `Player.log` 落在 `LocalLow\Mengoo\MCLocalLauncher\` | ✅ 实测 |
| 日志是标准 Unity `Debug.Log` 格式（带 Filename/Line） | ✅ 实测 |
| 实验内部步骤（术中 3/10 那种）会写进日志 | ❓ 仍需一次真正进实验的运行 |
| 启动器能登录、下载实验包 | ❌ 这台机器无平台网络，未验证 |

最后一条是**环境缺口**，不是技术缺口：给这台机器一条到 `skeletaltraction.cqmu.edu.cn`
的路（或把 Wine 前缀的代理指向 Mac 的 7897），就能继续往里走。

## 5. 对我们方案的影响

1. `client-agent` 的日志路径不用改——Windows 与 Wine 下完全一致；
2. 解析规则已有 `/raw` + `rules.json` + `calibrate.mjs`，拿到真日志即可秒级标定；
3. 「Linux 跑不起来」的旧结论作废：**ARM 模拟失败 ≠ x86 Linux 失败**。
