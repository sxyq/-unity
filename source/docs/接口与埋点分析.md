# 骨牵引实验平台 · 接口与埋点分析（实测版）

> 分析对象：`https://skeletaltraction.cqmu.edu.cn`
> 时间：2026-11-13 ｜ 账号：无可用登录凭据，全部为未登录态实测
> 采集工具：`craft-anything-cli web-walkthrough-record`（CDP，保留请求/响应体）+ Playwright 补充探测
> 原始证据：`docs/evidence-api-capture.json`

---

## 一、部署形态（先说结论）

**它不是 Unity WebGL 网页，而是「平台 SPA + 客户端实验」两段式架构。**

| 层 | 事实 | 证据 |
|---|---|---|
| 平台前台 | 梦之路（Mengoo）Vue3 + Naive UI 单页应用，挂在 `/mengoo/` | 主包 `index.175edf54…js`，53 个 modulepreload，vue-router + pinia + axios |
| 实验本体 | **客户端实验**（type=2），Unity 内容不在浏览器里 | `POST /api/Experiment/Item` 返回 `type:2, typeName:"客户端实验", url:"HLF10631030", isScore:1` |
| 列表标识 | 实验卡片带「客户端」标签 | `/mengoo/Course` 渲染结果 |
| Unity 痕迹 | 平台包内零命中 | 全量搜索 `UnityLoader / unityInstance / .unityweb / SendMessage / Module` 均 0 条 |
| 实时通道 | **没有 WebSocket** | 两次 walkthrough 全程 `websockets` 事件族为空，只有 `frame-navigated` |

所以「读取 Unity 内部步骤」这件事，在浏览器侧**没有入口**——不是没找到，而是这个部署形态本身就没有。

### 2.4 登录请求契约（实测）

> **2026-11-14 更新（Windows 复核）**：未登录访问 `/mengoo/`、`/mengoo/CourseInfo?id=…` 会 302 到
> `/rump_frontend/login/`，再跳 `https://cas.cqmu.edu.cn/cas/login?service=…`（CAS 单点登录）。
> 但 `/mengoo/login?redirect=/` 仍提供「密码登录」页签，账号 + 密码可直接登录（首屏无验证码）。
> 登录后 `Experiment/Launch`、`GetProcess`、`ExperimentResult/ItemsByUser` 均正常返回（已实测）。

用一次**无效账号**（`00000000`）提交登录，只为观察请求结构，不做任何猜测或绕过：

```http
POST /api/auth/UserNamePwd
{"userName":"00000000",
 "pwd":"FnvMscncZofdVjWzRvgxJH6h6qBnYUPkCoY0RmbkBls=",
 "uuid":"A35D9131-BA12-A0BB-A15E-9896B6C6A6E2",
 "code":""}
→ 200 {"code":-1,"msg":"账号或密码不正确"}
```

三个关键事实：

1. **密码不是明文**，是前端加密后的 44 字符 base64（32 字节密文 → AES）。
2. `uuid` 是前端生成的 GUID，**不是验证码图片的 id**。
3. `code` 可以为空，**首屏没有强制图形/滑块验证码**。

也就是说：拿到真实学号/工号后，用正常页面登录（让页面自己加密）即可，不需要逆向加密算法；只有连续失败后才可能触发验证码。

### 2.3 鉴权与状态保存

- `localStorage.token` 存在且被 **CryptoJS 加密**（`U2FsdGVkX1…` 开头，AES 格式），`userInfo` 同样加密存储。
- 路由守卫：`meta.requiresAuth` 为真的路由（`/MyScore`、`/CurriculumLearning/work`）会跳 `/mengoo/login?redirect=…`。
- 但 `ExperimentManage/ExInfo?id=…` **没有跳转**，页面渲染空白——说明它的守卫只判断 token 存在性，与后端校验脱节。这是平台的一个小 bug，不是可用的入口（页面没有数据）。

## 三、能不能「植入」？分三层看

### 3.1 平台层（浏览器里的那些页面）——**可以植入**

| 能力 | 可行性 | 做法 |
|---|---|---|
| 挂载外部 UI | ✅ 已实现 | content script + Shadow DOM，实测在真实站点首页/实验中心正常显示 |
| 读到实验身份 | ✅ | 从 `/api/Experiment/Item` 的 `id / code / type` 或 URL 的 `?id=` |
| 读到登录态 | ⚠️ 不建议 | token 加密存储，取用等于碰凭据；已明确不做 |
| 拦截/改写请求 | ❌ 不做 | 需求与合规都禁止；我们只读 `performance` 条目 |
| 埋点 | ✅ | 路由变化、接口调用、面板交互，全部可记录（见第四节） |

### 3.2 实验层（Unity 客户端内部）——**无法植入**

- 没有 `iframe`、没有 `postMessage`、没有 `unityInstance`，浏览器拿不到任何内部状态。
- 客户端的启动参数由 `/api/Experiment/Launch` 下发，**必须登录**才能拿到；即便拿到，那也是一个本地程序的启动参数，不是网页。
- 结论：**「自动识别术中第几步」在当前部署形态下不可能实现**，只能人工选择。这是形态决定的，不是实现偷懒。

### 3.3 折中方案——**已经落地**

- 平台层能识别到「进入哪个实验、是不是考核页」；
- 实验内部的阶段/任务/术后天数，用下拉框手动指定；
- 两者共用同一套 `{phase, postopDay, scenarioId, …}` 结构，将来若有真接口，只换数据源不改 UI。

## 四、埋点：能做到什么程度

已在 `apps/apps/extension/src/instrument.js` 实现本地闭环埋点，**不写原系统、不上传服务器**。

| 事件 | 触发点 | 附带信息 |
|---|---|---|
| `mount` | 组件挂载 | 页面 URL、视口尺寸、停靠位 |
| `scene` | 场景变化 | from/to 场景、是否自动、证据来源、置信度 |
| `postop-day` | 术后天数变化 | 第几天、自动还是手动 |
| `panel` | 打开/收起/关闭 | 动作类型 |
| `drag` | 拖动结束 | 坐标 |
| `ask` | 学生提问 | 问题前 120 字、长度、当前场景快照 |
| `answer` | 回答结束 | 结束原因（done/aborted/error）、字数 |
| `cancel` | 主动停止 | — |
| `score` | 粘贴成绩 | 文本长度 |
| `ui` / `config` / `settings` | 界面与模型设置 | 改了哪个键、值 |
| `error` | 请求失败 | 错误信息 |

存储：`localStorage.bt_trace_v1`，环形缓冲 600 条；面板「设置 → 埋点」可看统计、复制 JSON、下载 CSV（带 BOM，Excel 直接打开）。

**平台层可埋但没有做的**：全局路由 hook、接口成功率统计。原因：需要注入页面主世界（MAIN world），侵入性明显上升，收益不大。如果要，建议单独做一个只读的 analytics content script。

## 五、登录与成绩：卡在哪一步

1. **没有真实学号/工号**——需求里只给了「工号 + 固定前缀」的口令规则，没有具体号码。这是唯一的硬阻塞。
2. 登录请求契约已经拿到（见 2.4），首屏无验证码，用正常页面登录即可，**不需要破解前端加密**。
3. 即便登录，成绩仍需 `token` 调 `/api/ExperimentResult/ItemsByUser`；在扩展里读 `token` 等于碰凭据，不做。正确做法是登录后由页面自己取数、再经用户授权交给组件。

所以成绩走「学生粘贴 → 本地解析」的合法路径，界面上明确写清「不填则只给一般性建议」。

## 七、一句话总结

平台层的信息够用（实验身份、考核页判断、页面状态），实验内部的信息在浏览器侧**根本不存在**。所以本方案把「能自动的自动、不能自动的让人选」做成了同一条数据管线，而不是假装能读 Unity。

## 八、启动链路：从「启动虚拟实验」到实验真正跑起来

这一节是把 416 个 JS chunk 全量拉下来静态分析后得到的（`craft-anything` 出的包，人工 grep 定位），
关键文件是 `BaseLearning.7d1c7707….js` 与 `baselarning.4f12539f….js`。

### 8.1 平台按 ProjectType 分两种运行形态

`BaseLearning` 组件的模板里写死了分支：

| ProjectType | 运行方式 | 代码证据 |
|---|---|---|
| 1 / 4 | **iframe 内嵌** `ExUrl` | `<iframe id="Iframe" src={ExUrl}>` |
| 2 / 6 / 7 | **客户端**：显示「启动虚拟实验」按钮 | 出现「插件下载 / 客户端实验安装说明.pdf / 下载插件」 |
| 3 | 新标签页打开 `ExUrl` | `window.open(ExUrl, "_blank")` |
| 8 | 视频实验 | `vue3VideoPlay` |

本项目是 **type=2**，落在「客户端」分支。

### 8.2 点「启动虚拟实验」之后发生了什么（已用真实学生账号验证）

```js
async function te(){
  const e = await Launch({id});                 // POST /api/Experiment/Launch
  if(!e.error){
    Xa(e.data.url).ticket;                       // 解析 url 里的 ticket 参数
    const t = e.data.url;
    openUri(t, () => {                           // 唤起失败 → 提示装插件
      window.open(e.data.launcherUrl);           // 下载 MLauncher
    });
  }
}
```

`openUri()`（`baselarning` 里）的实现是本项目最关键的一段：

```js
const ws = new WebSocket("ws://127.0.0.1:9090/");   // 本地启动器
ws.onopen    = () => ws.send("Hello from client");
ws.onmessage = () => { window.location = url; ws.close(); };   // 握手成功才跳转
ws.onerror   = () => { /* 回退到 msLaunchUri / 自定义协议唤起 */ };
```

三个可直接利用的事实：

1. **本机常驻一个 `ws://127.0.0.1:9090/` 的启动器服务**（MLauncher，Windows `.msi`）。
2. `Launch` 返回 `{url, launcherUrl}`，`url` 带 `ticket`，被赋给 `window.location`。
3. 握手成功 = 启动器已安装；失败 = 弹「检测你的电脑没有安装 mengoo 下载器」。

**实测**（学生账号已脱敏，点击「启动虚拟实验」后抓到的完整响应）：

```json
POST /api/Experiment/Launch  {"id":"84A5ABB7-6DE6-4382-8D8D-819270690E70"}
→ {"data":{
     "type": 2,
     "ticket": "<redacted>",
     "launcherUrl": "/MZL/MLauncherSetup.msi",
     "url": "MLauncher://&HLF10631030&&&&Chinese&https://skeletaltraction.cqmu.edu.cn&&&&&&&&&&<redacted>&3&https://skeletaltraction.cqmu.edu.cn&2&HLF10631030&"
   }}
```

按 `&` 拆开：

| 位置 | 值 | 含义 |
|---|---|---|
| [1] | `HLF10631030` | 实验代码 |
| [5] | `Chinese` | 语言 |
| [6] [18] | 平台地址 | 回连地址 |
| [16] | `<redacted>` | ticket（会话票据，已脱敏） |
| [17] | `3` | 模式/版本位 |
| [19] | `2` | ProjectType |
| [20] | `HLF10631030` | 实验代码（重复） |

**结论（已确证，非推断）**：`url` 是 `MLauncher://` **自定义协议**，浏览器把控制权交给本机启动器，
由它拉起 Windows 客户端。**浏览器侧不存在可访问的实验 DOM，自动识别 Unity 内部步骤在这里是物理上不可能的。**
证据文件：`docs/evidence-launch.json`。

### 8.3 但如果走 iframe 形态，就完全可集成

`BaseLearning` 里有这样一段（这是平台与实验内容之间的**唯一正式通道**）：

```js
window.addEventListener("message", le);

function le(e){
  if (e.data.includes("///")) {
    const t = e.data.split("///")[1];
    ScormDataUpload({ id, data: t, batchNO, courseStudyDataId });   // 步骤上报
  } else if (e.data.includes("***")) {
    const t = e.data.split("***")[1];
    JsDataUpload({ ...JSON.parse(t), id, courseStudyDataId });      // 结果/成绩上报
  } else if (e.data.includes("$$$"))   { ReloadInfo();  }
  else if (e.data.includes("￥￥￥"))   { ReloadScore(); }
  else if (e.data.includes("~~~"))     { resetTime();   }
}
```

对应接口：

| 上报 | 接口 | 用途 |
|---|---|---|
| `///<data>` | `POST /api/open/ScormDataUpload` | 步骤（SCORM 数据） |
| `***<json>` | `POST /api/open/JsDataUpload` | 结果/成绩（JSON） |

**这意味着：只要实验以 iframe/网页形态运行，页面就能收到结构化的步骤与成绩消息。**
扩展只需要旁听同源 `postMessage`，就能拿到比 DOM 文本可靠得多的状态信号。

### 8.4 本项目已按这条通路做好接入

- `apps/apps/extension/src/bridge.js`：旁听 `/// *** $$$ ￥￥￥ ~~~`，解析成 `step / result / reload-*` 事件
- 识别到事件后，面板页脚显示「已接入实验事件 N」
- 报告阶段自动把 `***` 里的 JSON 填进成绩框（不再需要学生手贴）
- 全程只读：不发送、不拦截、不改写

联调页：`http://127.0.0.1:8787/demo/bridge-test.html`（模拟平台学习页 + 实验上报）

### 8.5 实验身份：线上页面已经能自动认出来

学习页 URL 带 `?id=`，而 `/api/Experiment/Item` 是**登录前就能调**的公开接口。
所以现在打开任意带 `?id=` 的平台页面，面板副标题会直接显示：

### 11.5 REA 自己声明的局限（照抄，不美化）

- 静态发现是"观察或有界推断"，REA **不执行**捕获的 JS；
- 字符串拼接的路径、加密配置、服务端行为仍属未知；
- 端点候选按脚本/值/检测器去重，不等于运行时出现次数；
- `completeness: complete` 只描述"已检查捕获到的源码"，不是调用点普查。
