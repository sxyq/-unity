# 客户端状态识别与叠加方案（无源码）

> 目标：解决"实验跑在 `MLauncher://` 拉起的 Windows 客户端里，浏览器读不到它"这件事。
> 结论：**不改客户端、不读内存、不注入进程**，靠"客户端自己写在本机的日志 + 窗口标题"就能拿到阶段。
> 本机（macOS）已用模拟日志验证通路；Windows 上需要按 §5 的清单实测一次真实日志格式。

---

## 1. 从安装包里挖到的确定事实

`MLauncherSetup.msi`（82 MB，公开下载）解包后（OLE → CAB → 128 个文件）：

| 文件 | 说明 |
|---|---|
| `MCLocalLauncher.exe` + `MCLocalLauncher_Data/` | 启动器本体，**Unity 程序** |
| `MCLocalLauncher_Data/Managed/AssemblyCSharp.dll` | 启动器自己的 C# 代码（115 KB，可读） |
| `MCLocalLauncher_Data/app.info` | 内容是两行：`Mengoo` / `MCLocalLauncher` |
| `Version.json` | 版本 `2023.1020.1014`，123 个文件的清单 |
| `MCLocalLauncherService.exe` / `InstallService.exe` | 安装与常驻服务 |
| `UnityPlayer.dll`、`data.unity3d`(34 MB) | Unity 运行时与资源 |

从 `AssemblyCSharp.dll` 的字符串表读到（UTF-16，非 ASCII 也能取到）：

```
GMLoginType / GMSceneConfig / GMMedicalStepType / GMMedicalSubStepType
GMOperationalScoreResult / GMScoreRuleType / Assessment_GradingItems_8090901…
Operation_SubStepDescription_70101 … 70501
LoadSceneStart / LoadSceneEnd
PrintLog / PrintLogError
FindProcessWindow / GetWindowThreadProcessId / KillGameProcess / StartGame
/api/open/GetExperimentInfo
http://res.cs-vstep.com/device/CXLauncher/VersionList.ini
```

四件事被证实：

1. 启动器会**读写 Unity 日志**（`PrintLog`），并按场景/步骤命名（`LoadSceneStart`、`GMMedicalStepType`）；
2. 启动器用 `StartGame` 拉起实验进程，并且**已经具备"找窗口"的能力**（`FindProcessWindow`）；
3. 它和平台之间只有一个接口：`/api/open/GetExperimentInfo`（启动参数由平台 `Launch` 给）；
4. 厂商更新源是 `res.cs-vstep.com`（上海梦之路）。

### 日志路径（可直接推导）

Unity 的 `Player.log` 路径规则是 `%USERPROFILE%\AppData\LocalLow\<company>\<product>\Player.log`，
而 `app.info` 明确写了 `Mengoo` / `MCLocalLauncher`，所以：

```
C:\Users\<用户>\AppData\LocalLow\Mengoo\MCLocalLauncher\Player.log
```

实验本体（HLF10631030）如果是另一个 Unity 进程，它的 company/product 需要在那台机器上看一眼，
`client-agent` 会把 `LocalLow` 下所有 `*\*\Player.log` 都扫一遍，不需要提前知道名字。

## 2. 采集代理怎么工作

`client-agent/agent.mjs`（Node 18+，Windows/macOS 都能跑）：

```
读 Player.log 末尾 256 KB
   → 按规则匹配阶段（术前/术中/术后第 N 天/考核）
   → 再读前台窗口标题（Windows，PowerShell 调 user32）
   → 合并成统一结构，200ms 内返回
GET http://127.0.0.1:8790/state
```

输出就是项目约定的场景结构：

```json
{
  "phase": "intraop",
  "postopDay": null,
  "mode": "study",
  "contextSource": "client-log",
  "confidence": "high",
  "evidence": ["Operation_SubStepDescription_70101 皮肤消毒"],
  "logs": [{"file": "…Player.log", "events": 5, "phase": "intraop"}]
}
```

它**只读文件**、**只读窗口标题**，不注入、不改文件、不发网络请求。

### 置信度规则

| 情况 | confidence |
|---|---|
| 日志里出现 ≥3 条阶段证据 | high |
| 1–2 条 | medium |
| 日志没有，靠窗口标题 | low |
| 都没有 | none → 面板继续用"手动选择" |

页面识别优先级高于客户端日志：页面能识别时用页面；页面识别不到才回落到客户端。

## 3. 两条链路都已接通（本机实测）

```
浏览器扩展  ──(内容脚本直连 127.0.0.1:8790)──┐
                                            ├─→ client-agent → Player.log
服务端注入  ──(/mengoo/__ai/api/state)──────┘
```

实测（模拟日志内容为「术中阶段 3/10 术中沟通」）：

| 场景 | 结果 |
|---|---|
| 扩展 + 真实平台首页（页面无实验信息） | 面板自动变「智能情境化护患交流｜术中沟通与宣教」，标注 `自动` |
| 服务端注入（8899 预演） | 同上，`hook.js` 通过 `/api/state` 拿到同一份状态 |
| 日志清空 | 回到「未识别，请手动选择」，不猜 |

## 4. 悬浮窗（不改客户端的"贴着看"）

`client-agent/overlay/` 是一个 WinForms + WebView2 的小程序：

- 无边框、置顶、不占任务栏
- 只在**标题匹配**（骨牵引/虚拟仿真/Mengoo/MLauncher/实验）的窗口出现时贴到它右侧
- `Ctrl+Alt+A` 显示/隐藏，可拉伸，加载 `http://127.0.0.1:8788/panel.html`

它和"嵌进客户端"的区别：**是两个窗口叠在一起**，客户端一个字节都没改。

> ⚠️ 这份 C# 代码在 macOS 上无法编译，**未在 Windows 实机验证**。
> 构建：`dotnet build -c Release`（需 .NET 8 SDK + WebView2 Runtime）。

## 6. 边界（写清楚，避免误解）

- 能拿到：**阶段**（术前/术中/术后第几天/报告）、**是否在考核**（标题或日志关键词）；
  当日志出现 `CurrentTask / 当前任务 / SubStepDescription` 等**明确任务标记**时，额外拿到**任务**
- 拿不到：牵引重量、观察结果等**具体参数**（除非日志里打印）；没有任务标记时**不拿阶段猜任务**
- 不会做：注入进程、读写客户端内存、修改客户端文件、Hook DirectX
- 日志解析失败时：`confidence: none`，面板回落到手动选择，**不猜**
