## 一、完整流程：六步，两个世界

```
① 首页  →  ② 实验详情  →  ③ 点「开始学习」  →  ④ 运行页（启动虚拟实验）
                                                      │
                                              ⑤ 弹「未安装下载器」/ 拉起 MLauncher
                                                      │
                                          ⑥ Windows 客户端里做实验（浏览器留在这里）
                                                      │
                                              ⑦ 完成回平台，刷新成绩
```

### ① 首页（`docs/flow/01-home.png`）

- URL：`/mengoo/`
- 可见：平台访问量、实验数量、热门实验（骨牵引 2400 次访问）
- 状态：无个人状态

### ② 实验详情页（`docs/flow/03-courseinfo.png`）

- URL：`/mengoo/CourseInfo?id=84A5ABB7-…`
- **这一页已经有个人状态**：
  - 学习总用时 **75 分钟**
  - 已完成 **3 次**
  - 当前学习进度 **0%**（进度条）
  - 实验评分 **10 分**（全站均分）
  - 成绩分布：优秀 63.88% / 达标 10.1% / 未达标 26.02%
- 按钮：`开始学习`

### ③ 点「开始学习」→ 运行页（`docs/flow/04-launch.png`）

同时抓到接口：`POST /api/Experiment/Start`（200，记录"开始学习"）。

### ⑤ 装了下载器之后

平台跳 `MLauncher://&HLF10631030&…&ticket…` → 拉起 Windows 客户端 → **实验全程在另一个进程里**。

浏览器仍停在④这一页，`学习进度` 不会再动（页面只在加载时取一次）。

### ⑥ 做完回平台

成绩出现在左栏与「个人中心-我的成绩」，需**手动刷新**。

## 二、平台到底暴露了哪些状态（实测抓包）

| 接口 | 返回 | 粒度 | 页面何时调用 |
|---|---|---|---|
| `/api/Experiment/GetProcess` | `{ppv:0, studyeds:3, timeUsed:4514}` | **当前用户**进度%、完成次数、累计秒 | 仅进入页面时 1 次 |
| `/api/Experiment/ItemData` | `{score:10, pageView:2401, studys:1822, timeUsed:834}` | 实验级统计 | 进入详情页 |
| `/api/ExperimentResult/ItemsByUser` | 3 条成绩明细（98/88/68…） | 当前用户成绩 | 运行页 |
| `/api/StudentCenter/ItemsMineScore` | 成绩列表 | 当前用户 | 我的成绩页 |
| `/api/Experiment/Start` | `{code:0}` | 开始学习事件 | 点「启动虚拟实验」时 |

**关键结论**：`GetProcess` 就是平台侧的"实时状态"字段（进度/次数/用时），
但**页面自己不轮询**——所以学生进客户端后，网页上的进度永远停在 0%。

## 三、我们补的那一环：把 `GetProcess` 变成实时

新增 `apps/apps/extension/src/api-poll.js`（MAIN world）：

1. 从页面自己的请求头里取它自己的 token（**只在内存，不落盘、不上传**）；
2. 每 8 秒调一次 `/api/Experiment/GetProcess`；
3. 结果送回面板，显示成一行：

```
平台实时进度 0% · 已完成 3 次 · 累计 75 分钟
```

实测（`docs/flow/06-progress-live.png`）：9 秒内触发 4 次 GetProcess，
面板正确显示上述文案。

这意味着：**只要客户端在做实验时向平台上报进度，网页侧就能实时看到 ppv 变化**，
而这一步不需要改客户端、不需要读 token 以外的任何东西。

## 四、嵌入点与提醒时机（按真实流程）

| 时机 | 页面 | 我们能读到 | 该做什么 | 可靠性 |
|---|---|---|---|---|
| 进实验详情之前 | 首页/列表 | 只有实验名 | 不打扰 | — |
| **进入详情页** | CourseInfo | 进度%、次数、用时、历史成绩、均分 | ① 显示面板；② 若已有 3 次成绩，主动问"要不要按上次 98 分做提升" | **高** |
| **点「开始学习」** | 运行页 | 同上 + 成绩明细 | 提示"先做术前访视？"（阶段=术前）| **高** |
| **点「启动虚拟实验」** | 运行页 + 弹窗 | 未装下载器 / 即将拉起 | 最关键的一次提醒：**"客户端会全屏，把浏览器放到另一块屏或缩小，我在这里同步"** | **高** |
| 客户端运行中 | 浏览器停在同一页 | `GetProcess.ppv`（每 8s） | 进度跳变→推断阶段：0–20% 术前、20–70% 术中、70–90% 术后、100 报告 | **中**（依赖客户端是否上报） |
| 客户端运行中（增强） | 本机日志 | `Player.log` 场景/步骤行 | 更细的阶段与任务 | **中低**（真实格式未验） |
| 完成回平台 | 运行页/成绩页 | 成绩明细 | 自动带入成绩做反馈，不用手贴 | **高** |
| 考核环节 | 考核页 | 页面"考核"字样 | 切 exam 模式、拒绝给答案 | **中**（介绍页误判已修） |

### 一句话的"提醒设计"

- **进入前**：告诉学生"你上次做到哪、这次重点是什么"（有数据）；
- **启动时**：告诉学生"客户端会盖住浏览器，怎么摆"（纯操作提醒，不需要实验状态）；
- **过程中**：进度变了就换阶段话术；进度没变就**不猜**，让学生手动选；
- **结束后**：直接拿真实成绩讲评。

## 五、还差哪一步才算"真正实时"

平台侧已经打通（`ppv` 每 8 秒刷新，实测有效）。
**唯一没闭环的是：客户端到底会不会在做实验时更新 ppv。**

- 会 → 上面整条链就是"实时"的，不需要任何客户端改造；
- 不会 → 只能退到本机日志/窗口标题，精度降到"阶段级"。

验证方法只有一个：找一台装了客户端的 Windows，做 5 分钟实验，
在浏览器这一页开着面板看进度百分比动不动。
